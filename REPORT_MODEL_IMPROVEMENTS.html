Reranker 改进汇报

1. 一页结论

  • 这轮工作的核心不是单纯调参，而是先修复了评估不可信的问题，再建立了可复现 baseline，最后在新数据上拿到了更强的模型。
  • 在老数据上，采用 新 item 划分 + 统一训练/评估口径 后，正式 baseline 的 ROC-AUC 从 0.7667 提升到 0.8509。
  • 在新数据 QC3511 上，同一套 test 集对比显示：
  • Base: ROC-AUC 0.7518 / PR-AUC 0.4972 / F1 0.5444
  • Old Model: ROC-AUC 0.8233 / PR-AUC 0.6282 / F1 0.6134
  • New Model: ROC-AUC 0.8801 / PR-AUC 0.7549 / F1 0.6897
  • 当前结论明确：New Model > Old Model > Base。

2. 起点问题

最早版本的问题不是模型太弱，而是评估口径不可靠。

  • 旧版按样本随机划分，同一商品会同时出现在 train/val/test，存在严重数据泄漏。
  • 在修复为 按 item 划分 后，最早一版实验结果明显下滑，暴露出真实泛化能力不足。
  • 这说明此前的高分很大程度上来自数据泄漏，而不是模型真正学到了 query-document 匹配能力。

3. 改进一：修复评估口径，建立老数据正式 baseline

我先固定了一套正式可复现 baseline：

  • 仍然使用老数据
  • 划分方式改成 按 item 划分
  • 训练统一为 pointwise prompt-BCE
  • 评估统一为 val 扫阈值 -> test 固定阈值

正式结果：

模型 Accuracy Precision Recall F1 ROC-AUC
Base 0.6619 0.5344 0.8205 0.6473 0.7667
Fine-tuned V4 0.7765 0.6849 0.7576 0.7194 0.8509

提升：

  • F1 +0.0721
  • ROC-AUC +0.0842

这一步的价值是先建立一个可信的旧数据对照组，后续所有新实验都能基于它比较。

4. 改进二：先优化召回输入，再做 reranker

在直接优化模型之前，我先分析了召回 TopK 配置，回答“应该给 reranker 什么候选集”这个问题。

结论：

  • 50/50 最省钱，但召回能力偏保守
  • 100/100 召回最多，但后半段质量下降明显，性价比一般
  • 100/30 是更平衡的方案：比 50/50 明显多拿高分词和核心词，但成本只小幅增加
  • 单路分析表明，如果继续放宽，应优先扩 dense，而不是更深地扩 sparse

5. 改进三：在新数据 QC3511 上建立新 baseline

在新数据上，我重新构建了训练集：

  • 总 item：3511
  • 原始 pair：421,569
  • 标签定义：final_score >= 2 为正类
  • item 内负采样：1:3
  • 最终样本总数：224,424

训练后得到 new_model，并和 base、old_model 放到同一套 QC3511 test 上做正面对照。

6. 最终结论

把这几部分串起来，这轮工作的改进可以概括为三步：

  1. 先修复数据泄漏和评估口径问题，让结果变得可信。
  2. 再通过 TopK 分析优化召回候选分布，让 reranker 的输入更合理。
  3. 最后在新数据 QC3511 上构建新 baseline，并证明新模型在同一套 test 上稳定优于基础模型和旧模型。

因此，这轮工作的核心贡献不是“把一个旧模型调高一点”，而是建立了一条从可信评估到合理召回再到新数据更强模型的完整改进链路。
