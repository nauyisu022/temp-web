Description 前置清洗方案

项目报告 · 2026-03-31 · Reranker / Title Optimization 团队

1. 动机

Shopee 电商商品的 description 字段是 KSP 卖点生成（P0）和标题优化（P4）的核心输入。但该字段普遍混杂大量运营性噪音：

Emoji / URL / 电话💎📦⚠️ · shopee.tw/... · +6016-661-6081噪音符号进入卖点

对 29 万条已有 KSP 输出的静态分析显示：

15.6% 含噪音的商品中，KSP 的卖点词来自被清洗掉的噪音文本——即物流/客服/促销内容直接"泄漏"进了 KSP 卖点。

2. 方案设计

2.1 设计原则

  1. 保守优先——只删除高置信度噪音，不确定内容一律保留，避免误删产品事实
  2. 保护规则优先于删除规则——含规格单位、型号、认证词、产地词的行，无论是否同时命中噪音关键词，强制保留

2.2 两阶段管线

原始 description
  → 阶段一: 预处理（结构清理，不涉及语义）
  → 阶段二: 行级过滤（依赖长度限制 + 噪音/保护词库）
  → 输出: description_cleaned

2.3 行级过滤逻辑

classify_line(line, region):
  1. 含规格单位 / 型号 / 认证词 / 产地词  → fact（强制保留）
  2. 行长度 > 100 字符                    → keep（混合内容安全保留）
  3. 命中噪音关键词库（6类×8地区）         → noise（删除）
  4. 其余                                → keep（宁可留多）

长度阈值（100字符）的作用：原始 description 中有 22% 只有单换行，整段内容被视为一行。当产品信息和物流信息混在一行时，超过 100 字符的行不删，防止误删产品事实。

8. 结论

核心结论
  1. 两阶段管线（预处理 + 行级过滤）设计简洁，逻辑清晰，易于维护
  2. 词库独立于代码（cleaning_keywords.json），扩展地区 / 增加关键词只改 JSON
  3. 规格/认证/产地保留率 100%，无误删产品事实
  4. KSP 噪音词来源减少 66.7%，搜索覆盖中性偏正
  5. TW 效果最显著（token 节省 16.1%）；建议优先在 TW 和 BR 上线

后续计划

  1. 完成人工标注（200 条，标注工具），基于结果补充词库漏检项
  2. 正式接入 P0 KSP，上线 AB test 验证标题质量提升
  3. 根据各地区运营反馈持续迭代词库（cleaning_keywords.json）
