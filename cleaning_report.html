Description 前置清洗方案

项目报告 · 2026-03-31 · Reranker / Title Optimization 团队

1. 动机

Shopee 电商商品的 description 字段是 KSP 卖点生成（P0）和标题优化（P4）的核心输入。但该字段普遍混杂大量运营性噪音：

噪音类型典型内容对下游的影响
物流发货Gratis ongkir · 出貨時間 5-7 天 · CODKSP 提取出"运费""发货"等词
退换货政策退貨須知 · 鑑賞期非試用期 · video unboxing标题中出现退货条款
客服联系whatsapp · 聊聊 · hubungi kamiKSP 含电话/聊天信息
店铺介绍歡迎光臨 · tentang toko · welcome卖点被店铺宣传稀释
促销/免责圖片僅供參考 · 色差 · atenção标题含免责声明
Emoji / URL💎📦⚠️ · shopee.tw/... · @gmail.com噪音符号进入卖点

对 29 万条已有 KSP 输出的静态分析显示：

15.6% 含噪音的商品中，KSP 的卖点词来自被清洗掉的噪音文本——即物流/客服/促销内容直接"泄漏"进了 KSP 卖点。

噪音污染的具体案例：

  • BR：KSP 中出现 frete por conta do comprador（运费由买家承担）
  • TW：KSP 中出现 代開發票（开发票服务）、經正常管道引進販售
  • VN：KSP 中出现 giá rẻ（便宜）、khuyến mãi（促销）

因此需要一个规则化的 description 前置清洗管线，在 P0/P4 之前过滤噪音、保留产品事实。

2. 方案设计

2.1 设计原则

  1. 宁可留多，不可漏删——只删高置信度噪音，不确定的一律保留
  2. 规格免死——含数字+单位（500g / 14CM / 4000mAh）的行强制保留
  3. 产地保护——含已知地名（Kerinci / 阿里山 / เชียงราย）的行保留，即使含主观词
  4. 行级输出——不拆句、不重组，输出保持原始格式，不引入额外换行

2.2 三级过滤管线

原始 description
  → Level 1: 预处理（HTML / 控制符 / Emoji / URL / 电话 / 去重 / 空白规范化）
  → Level 2: 段落级过滤（按 \n\n 分段，6类噪音关键词，全噪音段删除）
  → Level 3: 行级输出（逐行分类 fact/noise/keep，≤60字符短噪音行删除）
  → 输出: description_cleaned

2.3 Level 1：预处理（结构清理）

不涉及语义判断，仅清理非文本噪音：

2.4 Level 2：段落级过滤

按 \n\n 分段，对每个段落整体判断。判定逻辑：

含规格/型号/认证/产地词 → 整段保留（硬保护）
无噪音关键词           → 整段保留
有噪音关键词 → 逐行扫描:
    有 fact 行         → 整段保留
    全 noise           → 整段删除

2.5 Level 3：行级输出

对 Level 2 保留的段落逐行分类：

分类条件处理
fact含规格单位（500g）/ 型号（CB300F）/ 认证（Halal）/ 产地（Sumatera）保留
noise≤60字符 + 命中噪音关键词 + 无规格单位删除
keep其余保留

2.6 保护机制（免死规则）

任何文本命中以下任一条件，无论周围内容如何，强制保留：

4 类保护
类型示例
📐 规格单位500g · 4000mAh · 14CM · 128GB · 50ml
🔖 型号模式CB300F · YH-8004 · iPhone 15
✅ 认证词Halal · BPOM · FDA · ISO · SNI
🌍 产地词Sumatera · Kerinci · 阿里山 · เชียงราย · Đà Lạt · Minas Gerais

产地保护的意义：Teh terbaik dari perkebunan di lereng gunung Kerinci, Sumatera 含主观词 terbaik（最好的），但同时包含产地信息 Kerinci + Sumatera，整句保留。

5. KSP AB Test

5.1 实验设计

使用 sft_datagen_re/p0_ksp.py 的 4 步 KSP 提取管线（用户画像 → 关键词 → 候选生成 → 评估），在 AIS GPU 集群上对 1966 条商品分别跑：

  • Control（A 组）：原始 description → KSP
  • Treatment（B 组）：清洗后 description → KSP

模型：Qwen2.5-7B-Instruct，batch_size=64，每组约 15 分钟完成。

已知边界情况：

  • 物流限制含产品尺寸（45cm×30cm 为超商尺寸上限）→ 因含 cm 被保留（保守）
  • 店铺优惠券行（點關注領取10元優惠券）→ 无法匹配现有模式，保留（已知漏检）
  • 极短描述清洗后所剩无几 → 原数据质量问题

7. 接入方式

7.1 代码位置

reranker_sft_old/data/description_cleaner.py

7.2 API

from data.description_cleaner import clean_description

# 单条清洗
cleaned = clean_description(description, region)
# region: 'BR' | 'ID' | 'MY' | 'PH' | 'SG' | 'TH' | 'TW' | 'VN'

7.3 接入 P0 KSP（建议位置）

在 p0_ksp.py 的 load_items 之后加一行：

df['description'] = df.apply(
    lambda r: clean_description(r['description'], r['grass_region']), axis=1
)

无需修改其他管线阶段。

8. 结论

核心结论
  1. Description 清洗对 KSP 质量有净正向影响：噪音词来源减少 66.7%，搜索覆盖中性偏正
  2. 规格/认证/产地保留率 100%，无任何误删产品事实
  3. TW 效果最显著（token 节省 16.1%），因运营文案占比最高
  4. 清洗成本极低——纯规则引擎，秒级处理全量数据，无需 GPU
  5. 建议首先在 TW 和 BR 上线，后续扩展至全地区

后续计划
