GPT Keyword QC 标注设计文档

Reranker 训练数据 · 关键词质量控制

背景

Reranker 训练需要高质量的 (query, document, label) 三元组。上游 recall 系统（BM25 + Embedding）产出的关键词候选质量参差不齐，需要对候选关键词进行质量评分，筛选出适合注入训练的正负样本。

标注流程

1
构建输入
从 pair DB 或 P1 union 中读取商品-候选词对，按商品分组，附带完整产品上下文（title、brand、category、key_attributes 等）。
2
GPT 逐条评分
每次标注单位为一个商品 + 其全部候选关键词。模型在拿到完整产品上下文后，对候选词列表整体理解并逐条打分。
3
解析结果
从模型输出中提取每条候选词的 final_score 及辅助字段，写入 parsed JSONL。
4
生成训练数据
按分数阈值划分正负样本，输出 training_pairs JSONL 供 reranker 训练使用。

打分标准

双轨判断

正确性（Correctness）

  • 该关键词是否描述的是这个商品？
  • 检查类型、品牌、型号、规格、变体、配件 vs 主品
  • 有明确冲突的直接判 reject

价值（Value）

  • 即便正确，这个词作为训练信号有多大用处？
  • 过于宽泛、通用、冗余的词价值低
  • 精确描述商品核心身份的词价值高

最终评分 final_score

3
核心关键词
精准命中商品主体，应排在最前
2
正确但非最优
相关且可用，但不是最佳核心词
1
弱相关
部分相关，过宽泛或置信度低
0
错误或不适用
品牌冲突、型号不符、配件混淆等
  • 3 分需严格把控，只给最清晰的核心词
  • 一个词可以是正确的，但仍只值 2 分
  • 一个词可以是相关的，但仍只值 1 分
  • 不因词稍宽泛就直接给 0，应给 2 或 1

辅助字段

final_score 是最终使用的训练标签，辅助字段用于人工审核和错误分析。

字段维度取值
match_label正确性keep / borderline / reject
injection_value价值high / medium / low
reject_reason拒绝原因10 类枚举，见下节
short_reason说明模型的简短文字解释

拒绝原因分类

类别含义
brand_conflict品牌不一致
category_mismatch商品类目不符
spec_conflict规格 / 型号冲突
wrong_product完全不是这个商品
accessory_vs_main配件与主品混淆
region_mismatch地区不匹配
language_mismatch语言不匹配
info_intent_mismatch信息查询词，不适合商品匹配
low_relevance相关性过低
low_injection_value正确但注入价值不足

候选词来源标记

每个候选词带有来源路由标记，供模型参考，不作为打分依据。

B
Both
BM25 + Embedding 双路均命中
S
Sparse
仅 BM25 命中
D
Dense
仅 Embedding 命中

来源顺序只是弱提示，不代表质量高低。靠前的词不一定正确，靠后的词如果最相关仍可得高分。

执行方式

两种模式输出格式完全一致，解析逻辑可复用，可按场景互换使用。

大批量 · 生产

Batch 模式

提交后异步等待结果，适合大规模生产标注。支持 submit / poll / download / parse 四个子命令。

小批量 · 调试

Sync 模式

并发实时调用 API，适合小批量测试和快速验证 prompt 效果。
